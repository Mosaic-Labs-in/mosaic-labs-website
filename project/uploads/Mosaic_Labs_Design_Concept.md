# Mosaic Labs — Exact Website Design Concept

## Purpose

This document defines the visual and interaction concept for the Mosaic Labs website.

This is a design-direction document. Preserve the creative intent exactly. Do not replace the concept with a generic SaaS landing page, generic AI website, or conventional startup homepage.

The core visual metaphor is:

**Pieces → Mosaic → Data → Structure → Useful intelligence**

The website should feel like one continuous visual story rather than a collection of unrelated sections.

---

# 1. OPENING SCREEN — THE PUZZLE

The website initially opens on a completely blank white screen.

- Full viewport.
- Pure/minimal white background.
- No navbar.
- No standard hero section.
- No large marketing copy initially.
- The experience should feel intentionally empty and intriguing.

At the exact center of the screen is an empty puzzle/mosaic slot.

The outer boundary/silhouette of the slot is based on the **Mosaic Labs logo**.

There are exactly **four puzzle pieces** scattered around the screen.

The pieces belong to the central logo and need to be assembled.

### User interaction

The user is prompted to complete the mosaic.

Possible subtle prompt:

> Complete the mosaic

The four pieces should be draggable.

The interaction should feel sophisticated and tactile, not like a children's puzzle.

When a piece approaches its correct location:

- It should subtly attract toward the correct position.
- It should magnetically snap into place.
- The snap should have a satisfying but restrained animation.
- Incorrect placement should not permanently lock the piece.

The user completes all four pieces.

---

# 2. PUZZLE COMPLETION — LOGO REVEAL

When the fourth piece is placed correctly:

1. The final piece snaps into position.
2. The complete logo briefly holds.
3. The logo changes colour.
4. It then solidifies into **black**.
5. The logo enlarges dramatically.
6. It moves into the upper area of the screen, eventually settling toward the top-left/top region.

This should feel like the puzzle has transformed into the actual brand identity.

The transition should be cinematic and smooth.

Do not abruptly switch screens.

---

# 3. BRAND INTRODUCTION

Once the logo has moved into position, introduce the brand with very large typography.

Primary statement:

> **Hi, we're Mosaic Labs.**

Follow with:

> **Here for all your data needs.**

The typography should be oversized, confident, clean, and editorial.

The screen should remain minimal.

Do not fill the screen with cards, buttons, icons, gradients, or unnecessary UI.

There may be a subtle continuation prompt, for example:

> Explore ↓

or

> See what we build ↓

The exact microcopy can be refined later, but there must be an intuitive way for the user to continue.

---

# 4. THE MAJOR VISUAL SWITCH

When the user proceeds, the visual environment changes dramatically.

The screen transitions from:

**WHITE → BLACK**

The next scene should feel like entering the internal world of Mosaic Labs.

The transition should be deliberate and cinematic rather than a basic fade.

---

# 5. HUGE "MOSAIC LABS" TYPOGRAPHY

On the dark screen, display:

# MOSAIC LABS

The typography should be extremely large.

It should dominate the viewport.

The letters should initially appear as thick **white outlines/boundaries**.

The letters function as containers/windows into a world of data.

---

# 6. DATA INSIDE THE LETTERS

Inside the giant "MOSAIC LABS" letterforms, data-related visual elements begin appearing and blinking.

These should include visual representations of:

- Excel sheets
- spreadsheet cells
- CSV rows
- numbers
- graphs
- pie charts
- bar charts
- tables
- datasets
- coordinates
- data points
- database structures
- small dashboard fragments
- geometric data representations

The contents should continuously change, flash, rearrange, and move.

The effect should resemble a **flashback / rapid visual memory of data**.

The data appears to exist *inside* the letters.

The letters should feel alive.

Important:

The elements should form a cohesive visual language.

Do not use random stock icons.

Do not make it look like a generic icon cloud.

The viewer should feel that they are looking into a massive ecosystem of real-world data.

---

# 7. DATA ESCAPES THE TYPOGRAPHY

The visual elements inside the letters eventually begin escaping from the typography.

The data fragments start flowing outward.

They gather together and form a large flowing **wave / ray / channel of data**.

This is the main visual "WOW" moment of the website.

The wave is made from many individual data elements.

It can contain:

- numbers
- spreadsheet fragments
- CSV-like structures
- tiny charts
- tables
- data points
- nodes
- geometric particles
- dataset fragments
- other visual representations of structured data

The individual elements should remain visually interesting while collectively forming a fluid wave.

---

# 8. THE DATA WAVE MOVEMENT

The wave should:

1. Emerge from the "MOSAIC LABS" typography.
2. Flow outward.
3. Swirl across/around the logo typography.
4. Expand.
5. Become a large visual stream.
6. Travel downward through the page.
7. Become the transition into the main homepage.

The wave should feel like a river/channel of information.

It should not look like a standard particle animation.

It should feel intentional and branded.

The movement should be fluid, organic, and visually pleasing.

---

# 9. TRANSITION TO THE MAIN HOMEPAGE

As the data wave travels downward, the dark scene transitions into the main website.

The main homepage is built from a structured grid of **white tiles**.

The tiles should feel like a physical/digital representation of a mosaic.

Initially, the homepage is primarily white and minimal.

Then the data wave reaches the tile grid.

---

# 10. THE TILES LIGHT UP

When the wave touches the homepage:

- Individual white tiles gently illuminate.
- A warm yellowish light travels through the tiles.
- The illumination should propagate naturally.
- The tiles should subtly glow rather than become aggressively neon.
- The effect should feel like information activating a structure.

Primary yellow:

`#FFB502`

After the wave passes, the tiles settle back into their normal white state while retaining subtle visual life.

Then the rest of the homepage content reveals itself.

This represents:

**Raw data → structured system**

---

# 11. MAIN HOMEPAGE

Once the transition completes, the website becomes the actual Mosaic Labs homepage.

The page should retain the same visual language established by the opening sequence.

It should feel:

- Minimal
- Premium
- Technical
- Experimental
- Precise
- Editorial
- Futuristic without being cliché

Avoid:

- Generic SaaS layouts
- Excessive rounded cards
- Generic gradients
- Excessive glassmorphism
- Random particle backgrounds
- Stock-tech visuals
- Overloaded interfaces

Whitespace should remain important.

Typography should remain important.

Motion should remain important.

---

# 12. CORE BRAND VISUAL LANGUAGE

The entire site should be based on the idea of **data pieces coming together to form something useful**.

Visual motifs can repeatedly reference:

- mosaics
- grids
- tiles
- data points
- structured information
- datasets
- flowing information
- assembly
- transformation
- organization

The opening puzzle should therefore not feel like a disconnected gimmick.

It establishes the visual language for the entire website.

---

# 13. COLOUR PALETTE

Use this exact primary palette:

### Deep Burgundy
`#4D111C`

### White
`#FFFFFF`

### Dark Grey
`#272727`

### Yellow
`#FFB502`

### Light Beige
`#E5DED2`

Use colours intentionally.

White and dark grey should provide the primary neutral foundation.

Deep burgundy should establish brand character.

Yellow should be used selectively for interactions, active states, highlights, and the data-wave/tile activation.

Light beige can support secondary surfaces and visual warmth.

Do not use all colours equally.

---

# 14. LOGO BEHAVIOUR

The logo is an important interactive object, not merely a static header logo.

Its journey is:

**Puzzle outline → completed mosaic → colour transformation → black solid logo → enlargement → repositioning → giant outlined typography → data-filled typography → source of the data wave**

The logo/typography should therefore feel like the origin point of the entire experience.

---

# 15. CONTINUITY BETWEEN INTRO AND HOMEPAGE

The data wave should not simply disappear after reaching the homepage.

A small amount of motion can remain in the background or between tiles.

For example:

- occasional data particles moving between tiles
- subtle tile activation
- tiny data fragments travelling through the grid

The homepage should feel like it is still alive with data.

---

# 16. RESPONSIVE BEHAVIOUR

The concept must work on:

- Desktop
- Tablet
- Mobile

Do not simply scale the desktop version down.

On mobile:

- Adapt the puzzle layout.
- Make the four pieces easy to manipulate with touch.
- Adapt the huge typography to the viewport.
- Adapt the data-filled letters.
- Adapt the data wave.
- Adapt the tile grid.
- Preserve the story and sequence.

The interaction should remain understandable without requiring desktop-only behaviour.

---

# 17. MOTION PRINCIPLES

Motion should feel:

- Smooth
- Deliberate
- Cinematic
- Fluid
- Premium
- Responsive to user interaction

Use strong easing and carefully controlled timing.

Avoid:

- excessive bouncing
- cartoon-like motion
- random movement
- constant unnecessary animation
- distracting UI effects

Every animation should have a purpose.

---

# 18. PERFORMANCE PRINCIPLES

The visual experience is important, but it must remain performant.

The implementation should use the appropriate rendering technique for each effect.

Possible technologies may include:

- CSS
- SVG
- Canvas
- WebGL
- Three.js
- GSAP

Choose based on the actual requirements.

Do not add large libraries without a reason.

Use GPU-friendly transforms where possible.

Respect reduced-motion preferences.

Avoid unnecessarily heavy DOM-based particle systems.

The opening screen should load quickly and should not feel like it is waiting for a heavy application to initialize.

---

# 19. DESIGN PRIORITY

When making implementation decisions, prioritize in this order:

1. Fidelity to this creative concept.
2. Smoothness of the interaction.
3. Visual quality.
4. Brand consistency.
5. Performance.
6. Code simplicity.

Do not simplify the concept merely because a generic implementation is easier.

If something is technically difficult, find an appropriate technical solution rather than replacing the interaction with a standard website section.

---
